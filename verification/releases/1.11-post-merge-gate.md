## Offline private signing and verification

1. Download the exact GitHub Actions artifact linked above to a trusted local machine. Retrieve the **exact previously delivered** 1.10 APK. Confirm their SHA-256 values.
2. Extract only aligned.apk from the accepted CI ZIP into a private working directory. Check the aligned APK SHA-256 before signing.
3. On the local machine, use Android SDK build-tools 35.0.0 and **the original retained private signing key**, never the temporary CI signer. Supply the path, alias and passwords locally; do not place secrets in this repository, logs or CI:

       "$ANDROID_HOME/build-tools/35.0.0/apksigner" sign \
         --ks "$ORIGINAL_KEYSTORE" --ks-key-alias "$ORIGINAL_ALIAS" \
         --ks-pass env:LOCAL_SIGNING_STORE_PASSWORD \
         --key-pass env:LOCAL_SIGNING_KEY_PASSWORD \
         --out PassengerCount-1.11-signed.apk aligned.apk

4. Run the new fail-closed verifier from the repository, with the original-signed candidate and exact 1.10 APK:

       python3 scripts/verify-release-1.11.py \
         --ci-artifact /private/PassengerCount-1.11-validation.zip \
         --candidate /private/PassengerCount-1.11-signed.apk \
         --previous /private/PassengerCount-1.10.apk \
         --android-home "$ANDROID_HOME"

The verifier runs **offline**, opens no signing key, and publishes nothing. It requires exact CI ZIP, aligned APK and delivered 1.10 hashes; checks all compiled manifest, dex, resource, asset, vendor and data ZIP entries byte-for-byte against the accepted aligned APK; rejects unknown extra entries except recognized v1 signing metadata; verifies APK v2/v3 signatures, exactly one original signing certificate on both APKs, package app.passengercount, version 1.11/code12, min SDK26/target SDK35 and earlier 1.10/code11 identity using the **trusted local SDK's** aapt2 and apksigner on private, exact-byte snapshots. The CI artifact's included apksigner.jar is **never executed**. Any missing file, changed payload, unexpected ZIP entry, malformed signature, changed signer, missing tool or conflicting metadata **fails**, without a bypass.

## Still blocked before release

A passing offline binary check does **not** establish that installing over 1.10 preserves data. On a real device, install over the old APK **without uninstalling or clearing app data**, verify persisted surveys, native journals, upload receipts, destination permissions and export behavior, then test relevant precise/approximate/revoked location and screen-off foreground operation. Physical power-loss, API26 behavior, and supported live feed/provider scenarios remain separate, explicitly unverified gates. Record the exact tested APK SHA, signer, device/API, outcome and limitations. Obtain authorization for any public upload or release. Do not mark publication complete from this script.
